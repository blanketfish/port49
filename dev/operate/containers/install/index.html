    Install with containers¶

    Run the commands from deploy/compose/. setup runs as root at every up and copies each component's files into a volume of its own, so no volume holds both etcd identities:

    Volume Holds Mounted in
    port49d-etc port49d.yaml, policy, inventory, etcd CA, port49d's etcd certificate and key, secrets/encryption.key port49d, read-only
    port49d-keys the device keys, one file per version; the directory root:65532 0750, each file root:65532 0440 port49d, read-only at /run/port49/keys
    broker-etc port49-broker.yaml, policy, inventory, etcd CA, the broker's etcd and TLS files, secrets/broker-encryption.key port49-broker, read-only
    etcd-pki the CA and the three members' certificates and keys etcd-1..3, read-only
    etcd-root etcd's root certificate and key, and store-roles' output etcd-init only
    etcd-N-data each member's data that member
    broker-state broker.state_dir port49-broker
    port49d-spool the accounting spool port49d

    No secret is in any container's environment, so docker inspect shows none. Each secret is a file.

    Docker API access is root-equivalent

    docker run with a volume reads every file in it. Guard the Docker socket as you would the host.

    1. Build the images¶

    docker compose build

    To check, run docker image ls --filter 'reference=port49*:dev'. It lists port49-setup:dev and port49:dev.

    2. Bring your own PKI and secrets¶

    Put them under PORT49_COMPOSE_LOCAL, in the layout compose-pki writes: etcd/, broker/, keys/tacacs_v1 and secrets/encryption.key with secrets/broker-encryption.key. A device key is the shared secret you type into the device. The two sealing keys hold the same 32 bytes: make them once, with the setup image, and the command writes both files under those names. Make the device key the same way:

    docker run --rm -v "$PWD/local/secrets:/s" --entrypoint port49d port49-setup:dev \
  key sealing --dir /s --daemon-user 0 --broker-user 0

docker run --rm -v "$PWD/local/keys:/k" --entrypoint port49d port49-setup:dev \
  key device tacacs_v1 --dir /k --device-owner 0 --device-group 0

    To check, run ls -l local/keys local/secrets. The listing shows the device key and both sealing keys.

    3. Edit the config¶

    Edit config/policy.yaml and config/inventory.yaml. List each device by the address port49d sees. The example sets certificate_status.disabled, which a deployment must not. Then pick the sign-in backend.

    In config/port49-broker.yaml, replace broker.client_ca_file with the broker.identity block shown commented there. The broker must reach the provider's discovery and JWKS URLs; behind a proxy, set HTTPS_PROXY in the service's environment:. The rest is on OIDC sign-in.

    Replace the example's certificate_status with ocsp: or crls:. If your CA has no OCSP responder, use crls: before the first sign-in. See Client certificates.

    Uncomment the broker.directory: block in config/port49-broker.yaml and add a directory_password verifier. Put the keytab and krb5.conf, if the bind uses Kerberos, in the broker's configuration volume (broker-etc, under /etc/port49/), the keytab mode 0600 and owned by uid 65532. Set PORT49_SITE in the broker service's environment:. See Directory password and The directory.

    etcd's disk

    etcd needs sustained WAL fsync p99 under 10 ms. See Requirements.

    4. Start¶

    docker compose up -d

    etcd-init applies port49d store-roles' output once and enables auth. A later up changes nothing. To check, run:

    docker compose ps
curl 127.0.0.1:9049/readyz
curl 127.0.0.1:9050/readyz

    port49d and port49-broker show healthy, and both /readyz calls answer 200 serving. The port49d start line names all three etcd members at or above the floor (3.4.24, 3.5.8 or 3.6): see docker compose logs port49d.

    The shipped healthcheck probes with --ready

    That is right for docker compose. Docker Swarm restarts a container that turns unhealthy, so adapt both healthcheck blocks first. See Health checks.

    A published port may change the device's source address. Measured in L39: it is kept for an off-host device, and masqueraded to the compose gateway for a device on another Docker network on the same host.

    Unmeasured

    A connection that docker-proxy itself relays has not been measured.

    5. Keep broker.state_dir¶

    broker.state_dir holds the revocation marks, the witness and the issuing CA. Give each broker one named volume. Never use --scale, deploy.replicas or an anonymous volume. A second broker is a second service with a volume of its own. A fresh named volume copies uid 65532, mode 0700 from the image. A volume filled by hand and owned by root is not refused at start, but the first write fails. To fix it, run:

    docker run --rm -v <volume>:/s alpine:3.22 sh -c 'chown 65532:65532 /s && chmod 0700 /s'

    6. Make the issuing CA¶

    Only when the broker issues certificates. On one broker:

    docker compose exec port49-broker port49-broker init-issuer
docker compose restart port49-broker

    The broker loads the CA at start, so it needs the restart. A second broker must hold the same CA, or it refuses to start. Copy both files into its volume, then restart it:

    docker run --rm -v port49_broker-state:/a -v port49_broker2-state:/b alpine:3.22 sh -c \
  'install -o 65532 -g 65532 -m 0600 /a/issuing-ca.key /b/ && install -o 65532 -g 65532 -m 0644 /a/issuing-ca.pem /b/'

    To check, run docker compose logs port49-broker. The issuing as ... (sha256:...) line has the same fingerprint on every broker.

    7. Create the enrollment store¶

    Only for directory password sign-in:

    docker compose run --rm port49-broker init-enrollments

    Success prints created the enrollment store; password sign-in is on. A broker that is already running finds the store within 30 seconds, and until then its sign-ins answer enrollment_store_lost.

    8. First device and first login¶

    Add the device to the inventory and log in as a person (Log in). To check, run port49 ssh <device> -- show version. It prints the device's output, and the decision log holds a redeem record with verdict: permit.
