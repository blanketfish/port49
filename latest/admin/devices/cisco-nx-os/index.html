    Cisco NX-OS¶

    NX-OS 10.6(2)F over TLS honors the single-connect port49 offers it: with the offer the device asks port49 about the commands it runs, show users, a command port49 denies, among them (L80-cisco_nxos.md). Measured on Nexus 9300v 10.4(2)F (TCP only) and 10.6(2)F (TCP and RFC 9887).

    Reference configuration¶

    Load cisco_nxos.cfg (TACACS+ on port 49) or cisco_nxos-tls.cfg (RFC 9887, NX-OS 10.6(1)F or later). The placeholders table says what each placeholder is. Create the break-glass account by hand. The lines that matter, quoted from the files:

    feature tacacs+
aaa group server tacacs+ port49
  server <PORT49_1>
  server <PORT49_2>
  use-vrf <MGMT_VRF>
  source-interface <SOURCE_INTERFACE>
aaa authentication login default group port49 local
aaa authorization commands default group port49 local
aaa authorization config-commands default group port49 local
aaa accounting default group port49

    Over TLS, the lines that differ:

    tacacs-server secure tls
tacacs-server host <PORT49_1> port <TLS_PORT> single-connection
tacacs-server host <PORT49_1> tls client-trustpoint <CERT_ID>

    There is no deadtime line, on purpose: see the traps below.

    What the lab measured¶

    Over per-request TLS, the device's default, port49 offers single-connect and the device honors it: show users was asked about and denied by port49 (L80-cisco_nxos.md).

    The RFC 9887 client was measured on Nexus 9300v 10.6(2)F on 2026-10-18 (L73-cisco_nxos.md):

    • With no port configured the device dials 49, not 300, and it sends no server name (L73-cisco_nxos.md, cells a and c).
    • Every packet has the unencrypted flag set: port49d recorded no obfuscated_over_tls records (L73-cisco_nxos.md, cell b).
    • It sends its leaf and its intermediate certificate, and negotiates TLS 1.3 with TLS_AES_128_GCM_SHA256. It offered no session ticket (L73-cisco_nxos.md, cells e, f and g).
    • Given a server certificate naming only a DNS name, the login failed with the cause unproven; the device's next data came 5 s after the server's first. It refuses an expired certificate and one from an unknown CA with an alert (L73-cisco_nxos.md, cell d).
    • With single-connection the login reused the readiness probe's connection and opened no new one; without it one login opened 5 (L73-cisco_nxos.md, cell h).
    • After an alert at the handshake, break-glass logged in in 5.2 s, and the device never opened a connection to port 49 for the same host (RFC 9887 forbids a fall to plain TACACS+). After an ERROR reply it also landed, in 5.2 s (L73-cisco_nxos.md, cells i and j).

    Regression rerun pending

    The 2026-11 regression rerun of this measurement did not reproduce it, and the rerun is pending (#46). The results above stand as the lab register records them until a rerun says otherwise.

    Other measured behavior¶

    • A deny is never tried locally (L4-cisco_nxos.md).
    • With port49d stopped, break-glass logs in in 160 ms; with port49d dark, in 1.1 s; and with the first server resetting at accept, a token login reached the second in 1.1 s over TCP (L88-cisco_nxos.md, cells b, d and f). Over TLS on 10.6(2)F the same cells took 6.7 s, 1.2 s and 6.2 s, the latter after five connection attempts to the first server (L88-cisco_nxos-nxos106-tls.md).
    • While port49 is dark, commands in sessions that were already open ran under local authorization, so a command port49 would deny is then decided locally (L41-cisco_nxos.md, cell 3).
    • An ERROR does not make break-glass a way around port49's commands: the break-glass login lands and then every command is refused Error: AAA authorization failed (L4-error-cisco_nxos.md). Troubleshooting says what to do.
    • Break-glass with single-connection on, after port49d reset a de-admitted device's connection, was closed with the fix: on every declined path it logged in within 0.5 s of the key miss (L31-breakglass-cisco-singleconnection.md).
    • Sessions on one single-connect connection, offered and with single-connection: NX-OS 10.6(2)F takes replies out of request order, including a command authorization answered before the accounting record it was written behind. With three failing logins on the connection, a command answered in under 1 s; before port49 answered sessions at once it waited up to 7.3 s, and the device marked port49 dead 7 times and fell back once (L94-cisco_nxos.md).

    Traps¶

    • Set no deadtime: with a deadtime configured the device does not ask a server again until its minute has passed after the server returns, measured at 50 to 67 s (L4-error-cisco_nxos.md, section d).
    • Set the TLS port: with none the device dials 49, not port49d's listener (L73-cisco_nxos.md).
    • Over TLS, break-glass after an alert or an ERROR took 5.2 s in the lab, and the device's next data came 5 s after the server's first: allow for it (L73-cisco_nxos.md, cell i).

    Unmeasured¶

    Unmeasured: whether NX-OS checks port49's certificate status

    Whether NX-OS checks port49's revocation status, and SCEP, CMPv2, EST and ACME enrolment, were not measured: the lab used terminal enrolment and revocation-check none (the TLS note).

    Unmeasured: why the first TLS open fails

    Why the device's first nxos_ssl_open on a new connection fails before its retry succeeds about 5 s later is unknown, and so is one counter that read 3 in seven of eight fixed-arm cells with no fallback line beside it (the per-request TLS note).

    Unmeasured: the single-connect details and a restart

    The per-request TLS note (the note) is reported to record more than this page confirms, and none of it is confirmed here: that before the fix the device asked about some commands only and in one run show users ran; that three concurrent sessions shared one connection; that a session idle for 35 s reconnected cleanly; that a port49d restart in mid-session cost nothing on etcd but, on the memory store, denied every later command until the person logged in again; and that the first TLS open on a new connection can take about 5 s. Treat each as an expectation, and prefer etcd to the memory store if a restart must not cost a fresh login.

    Unmeasured: NX-OS without secure tls

    The reference sets tacacs-server secure tls on TLS hosts. What the device sends to the TLS port without that line is unknown: the lab did not run it, and no device debug was captured.

    Unmeasured: other NX-OS releases

    The lab ran 10.4(2)F over TCP and 10.6(2)F over TCP and RFC 9887. What other releases do is unknown.
