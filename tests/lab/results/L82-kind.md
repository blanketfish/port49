# L82: Kubernetes Secret volumes as port49d's key directory (kind)

Platform: kind v0.29.0, node image kindest/node v1.33.1 (digest pinned by the harness), on a GitHub-hosted
ubuntu-24.04 runner (image 20261026.354.1, kernel 7.0.0-1017-azure, Docker 28.0.4). External Secrets Operator
chart and app v2.12.0 (`fake` provider). Measured 2026-10-31.

Capture pointer: GitHub Actions run 41155086403, attempt 1, artifact `lab-l82` (`l82-results.md`,
`l82-cells.json`). The run before it (41151306253) stopped at an INVALID verdict: the results writer's key
guard refused a metric name used as a row's case. That is a harness fault, fixed in 23244e43; nothing was
measured differently.

## Observations

- (a) PASS. With `defaultMode: 0440`, `fsGroup: 65532`, `fsGroupChangePolicy: OnRootMismatch` the mount's
  directory is `root` mode `3777`, `..data` and the key links are `root` `0777` symbolic links, and the key
  file followed is `root` `0440`. The group prints as `UNKNOWN` because the stat pod has no entry for the
  fsGroup gid. port49d's pod was Ready with 0 restarts, so `fence.ReadSecret` accepts the layout.
- (b) PASS. A key added to the Secret reached a whole-volume mount in 1m3s (bound 180 s).
- (c) PASS. After 3m0s the whole mount's file had changed and the `subPath` file had not: "never by
  `subPath`" is confirmed.
- (d) PASS. The shipped ExternalSecret example (`creationPolicy: Owner`) put version 2 in the Secret 1s
  after the edit, and a login keyed with version 2 passed after 1m34s (bound 240 s) with no container
  restart. `port49_key_secret_files_changed` stayed 0, so no key was rewritten in place.
