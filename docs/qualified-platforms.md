## What an operator must do

- **Cisco Catalyst 8000V 17.13.01a**: When port49 answers ERROR (its store is unavailable) this device does not fall to its local method: the token login is refused and break-glass fails too (QUAL store_unavailable: break-glass logged in false). Keep a path that does not depend on port49 answering (console, or a second reachable server) for the time the store is down
- **Cisco Catalyst 8000V 17.18.02**: When port49 answers ERROR (its store is unavailable) this device does not fall to its local method: the token login is refused and break-glass fails too (QUAL store_unavailable: break-glass logged in false). Keep a path that does not depend on port49 answering (console, or a second reachable server) for the time the store is down
- **Cisco XRd control plane 26.1.1**: On generic XR (platform_set 1.3.0 has no cisco_iosxr adapter, so port49 renders no attribute) every command is refused locally with "% This command is not authorized" and the device asks port49 about none: it fails safe, but nothing works (QUAL note, "without a priv-lvl block"). Add to the policy file: platforms: {cisco_iosxr: {privilege: {readonly: ["priv-lvl=1"], operator: ["priv-lvl=1"], admin: ["priv-lvl=15"]}}}. Configure command authorization on the device too (aaa authorization commands default group <port49 group> local, as tests/lab/configs/xrd-startup.cfg has): without it port49 never sees a command, no role rule applies, and priv-lvl is the only bound. Only priv-lvl=15 was measured (it alone made XR send command authorization); level 1 was not. The claim that level 1 grants no more than the role is reasoning, not measurement, and holds only with command authorization configured
- **Cisco XRd control plane 26.1.1**: When port49 answers ERROR (its store is unavailable) XRd does not fall to its local method: the token login is refused and break-glass fails too (QUAL store_unavailable: break-glass logged in false). Keep a path that does not depend on port49 answering (console, or a second reachable server) for the time the store is down
- **Cisco Nexus 9300v 10.6(2)F**: Over per-request TLS (the device default) the device sent port49 no command authorization for the commands typed (QUAL tls_token_login); with single-connection on it did (QUAL tls_single_connection): configure single-connection on its TLS servers, or port49's command rules never see a command
- **Cisco Nexus 9300v 10.6(2)F**: Over per-request TLS a command port49's policy denies runs: the device asked port49 nothing and ran it (L80). Port49's command rules do not hold on this device over per-request TLS
- **Nokia SR Linux 26.7.2-519**: SR Linux needs a policy block or every login is refused, because platform_set 1.3.0 has no nokia_srlinux adapter and the generic adapter sends no priv-lvl (QUAL note, "without a priv-lvl block"). Add to the policy file: platforms: {nokia_srlinux: {privilege: {readonly: ["priv-lvl=1"], operator: ["priv-lvl=15"], admin: ["priv-lvl=15"]}}}. Set priv-lvl-authorization true on the device: its default false means port49 is never asked (L76 cell i); SR Linux's YANG says the session then gets full admin (srl_nokia-aaa.yang:254). Port49 command permit and deny rules never apply; the session role is the only bound (L76 cell b)
