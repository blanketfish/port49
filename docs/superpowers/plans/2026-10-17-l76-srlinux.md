**Goal:** Add Nokia SR Linux 26.7.2 (`ghcr.io/nokia/srlinux:26.7.2-519`) to the containerlab lab as an opt-in platform. **Architecture:**
- **The node.** One `kind: nokia_srlinux` node, `srl1` at 172.100.100.71, sits on the lab's existing management network `port49-lab`. It reaches port49d at 172.100.100.1:49 through SR Linux's `mgmt` network-instance.
- **The AAA config.** All of it is in `tests/lab/configs/srlinux-startup.cli`, which the topology references. containerlab applies it after the default config. Nothing is typed by hand.
- **The harness.** The existing harness (`tests/lab/harness_test.go`) handles bring-up, port49d, seed tokens, capture and SSH logins.
- **Mid-run changes.** The cells that change the device (i, j) use `docker exec <node> sr_cli`. That runs as the container's Linux root (containerlab starts the node as `0:0`, `nodes/srl/srl.go`), outside TACACS+, and puts the change back on every path.
- **The wrong-secret cell** changes the secret on port49's side, not the device's. The device keeps the published lab key, so the capture stays decodable and redactable.
- **What runs where.** Parsers, scrubbers, the leak gate, and the checks that the files agree are untagged and run under `make test`. The live test `TestL76` is `//go:build lab`.

**Where the image's YANG overrules the guide.** CLAUDE.md lab rule 4 applies: the device is right.
1. **The local group's name.** The guide's examples name the local server group `LOCAL-GROUP`. `srl_nokia-aaa.yang` constrains `server-group name` with "Server group name must be 'local' if and only if local server type is 'local'". This plan names it `local`.
2. **The accounting event.** The guide's accounting example is `event commands`. In `srl_nokia-aaa-types.yang`, `commands` has base `aaa_authorization_event_type`. The accounting event identity is `command`, base `aaa_accounting_event_type`. This plan writes `event command`.
3. **Per-command authorization.** `srl_nokia-aaa.yang` defines `grouping aaa-authorization-methods-config` (line 1096, holding `leaf-list authorization-method`) and `grouping aaa-authorization-events-top` (line 1123). No SR Linux native module `uses` either; `aaa-authorization-top` uses only `aaa-authorization-role-top` (line 1148). So the SR Linux native schema has no TACACS+ per-command authorization method, and the guide describes none.
   - The same image's `openconfig/system/openconfig-aaa.yang` does use both groupings (lines 696 and 731).
   - OpenConfig management mode is not measured here.
4. **The secret's port.** `srl_nokia-aaa-tacacs.yang` gives `port` default 49, and `secret-key` is up to 128 characters of cleartext.

The schema check (Task 5) re-reads 1–3 from the running image, so a wrong reading fails the run as INVALID rather than producing a note.

## Choices made by this plan (planner, 2026-10-17)

- **The node's identity.**
  - Selector `srlinux`, platform name `nokia_srlinux` (containerlab's kind name), node `srl1`, address 172.100.100.71 (L73 took .51 and .61).
  - The row is **opt-in**: it joins L73's `optInPlatforms`, so a run that names no platform never deploys it.
  - The inventory names its platform `nokia_srlinux`. port49 has no adapter for it, so it runs the generic adapter (spec §8 "Unknown platforms"). That is what this lab measures, deliberately.
- **Methods:** `authentication-method [ port49 local ]`. TACACS+ first, local second, so a dead port49 cannot lock anyone out (SA#aaa-server-group-configuration: if the last method is unreachable, the login is refused). `exit-on-reject` stays at its default `false` (YANG). Cell (d) measures what that means for a port49 deny.
- **Authorization:** `priv-lvl-authorization true` on the `port49` group, with two local roles, `p49-read` at priv-lvl 1 and `p49-admin` at 15. With the default `false`, the YANG says "authorization is skipped for TACACS+ users granting full admin access". Cell (i) measures that default.
- **Accounting:** `accounting-method [ port49 ]` with `event command { record start-stop }`, the image's spelling (see "Where the image's YANG overrules the guide").
- **The break-glass account** is `labcreds.BreakglassUser` with role `p49-admin`, not `superuser`. `superuser` sits behind the YANG feature `aaa-superuser`. A role needs no feature, and the guide documents it (SA#assign-roles-to-users).
- **Timeouts and health check** stay at their defaults (10 s and 30 s, YANG). The note records the defaults as the measured configuration.
- **No comments in the `.cli` file.** The comment syntax of a containerlab `.cli` startup file is not documented on CLAB#cli. The file's provenance is in `tests/lab/README.md` instead.
- **Order of cells:** schema, a, b, c, d, h, i, j, e, f, g.
  - Each cell that changes port49d or the device puts it back before the next.
  - e (wrong secret), f (stopped) and g (restarted) come last, because they leave the device's view of port49 disturbed.

## Review Focus

1. **The exec channel.** The harness logs in with SSH exec channels (`l.loginWithin`, 60 s per command). If SR Linux's sshd hands an exec command to something other than `sr_cli`, cell (a) gets empty output and reads it as "no session".
   - Cell (a) is INVALID when the session table has no row for the user. The fix is not `l.ptyCommands`: it drives `l.shell`, which expects a Cisco/EOS prompt and sends `terminal length 0`, syntax no SR Linux document cites (pre-flight I7). The fix is a cited SR Linux pty opener in a follow-up commit, with its prompt and paging command cited to the 26.7 CLI guide.
   - `TestL76SessionsReadTheGuidesTable` pins the parser, so a parse bug cannot pose as an exec problem.
2. **A change left on the device.** Cells (i) and (j) change the running config with `sr_cli`.
   - Each one restores in a `defer` and reads the result back (`e.set`).
   - A restore that does not read back is INVALID, so the next cell never runs on the wrong config.
3. **Secrets in device text.**
   - `info from running system aaa` shows `secret-key $aes1$...` and `password $y$...`.
   - The AAA log may print attributes.
   - containerlab's injected `ssh-key` lines carry the runner's `user@host`; `TestL76MaskConfigDropsSSHPublicKeys` pins their masking (Task 3).
   - `TestL76MaskConfigKeepsShapeAndDropsValues`, `TestL76FilterLogFollowsTheShellRule` and `TestL76LeaksFindsEverySecretAndShape` pin the scrubbers (Task 3).
4. **The leaf-list read in two layouts.** `info` prints a leaf-list inline (`[ a b ]`) or one entry per line. The schema check compares `authentication-method` with `[port49 local]`, and a misread would fail a good run. `TestL76LeafListReadsBothLayouts` pins it (Task 4).

func l76Claim() string {
	parts := make([]string, len(l76Cells))
	for i, c := range l76Cells {
		parts[i] = "(" + c.id + ") " + c.claim
	}
	return "Nokia SR Linux against port49 over TACACS+ on port 49, server group `port49` then `local`, " +

// l76LeafList reads `name [ a b ]` or the same over several lines, as
// `info` prints it.
func l76LeafList(text, name string) []string {
	re := regexp.MustCompile(`(?:^|[\s{])` + regexp.QuoteMeta(name) + `\s+\[([^\]]*)\]`)
	m := re.FindStringSubmatch(text)
	if m == nil {
		return nil
	}
	return strings.Fields(m[1])
}

var (
	// l76Hashed is a crypt-style hash or SR Linux's reversible key form
	// ($aes1$ for secret-key; $y$, $ar2$, $6$ for passwords).
	l76Hashed = regexp.MustCompile(`\$(?:aes1|ar2|y|[15689])\$\S*`)
	// l76Keyed is a secret-key or password statement and its value.
	l76Keyed = regexp.MustCompile(`(\b(?:secret-key|password)[ \t]+)(\S+)`)
	// l76Long is the lab rule's sed mask: 24 or more base64-ish characters.
	l76Long = regexp.MustCompile(`[A-Za-z0-9_+/=.-]{24,}`)
	// l76Word is a long run the mask leaves alone: a lowercase keyword joined
	// by hyphens or underscores, such as nokia-srl-authorization-role-netconf
	// or aaa_accounting_event_type.
	l76Word = regexp.MustCompile(`^[a-z]+(?:[-_][a-z]+)*$`)
	// l76SSHKey is an OpenSSH public key with its comment. containerlab
	// writes the runner's own public keys into admin-user and linuxadmin-user
	// `ssh-key` (its srl template), and the comment is user@host or an email.
	l76SSHKey = regexp.MustCompile(`(?:ssh-(?:rsa|ed25519|dss)|ecdsa-sha2-nistp\d+|sk-[a-z0-9-]+@openssh\.com)[ \t]+[A-Za-z0-9+/=]+[^"\]\n]*`)
	// l76DropLine is the lab rule's grep -v -i.
	l76DropLine = regexp.MustCompile(`(?i)password|token|secret|eyJ`)
)

// l76MaskConfig is device configuration made fit for a note: every SSH
// public key (with its user@host comment) and every hash masked, every
// secret-key and password value masked, the statements kept.
func l76MaskConfig(s string) string {
	s = l76SSHKey.ReplaceAllString(s, "<ssh public key masked>")
	s = l76Hashed.ReplaceAllString(s, "<masked>")
	s = l76Keyed.ReplaceAllStringFunc(s, func(m string) string {
		sm := l76Keyed.FindStringSubmatch(m)
		if sm[2] == "{" || sm[2] == "<masked>" {
			return m
		}
		return sm[1] + "<masked>"
	})
	return l76MaskLong(s)
}

// l76MaskLong masks every long base64-ish run that is not a keyword.
func l76MaskLong(s string) string {
	return l76Long.ReplaceAllStringFunc(s, func(m string) string {
		if l76Word.MatchString(m) {
			return m
		}
		return "<LONG>"
	})
}

// l76FilterLog is the lab rule's shell filter as code, for any device text
// that is not configuration: lines naming a password, token, secret or JWT
// are dropped, then hashes and long runs are masked.
func l76FilterLog(s string) string {
	var keep []string
	for _, ln := range strings.Split(s, "\n") {
		if !l76DropLine.MatchString(ln) {
			keep = append(keep, ln)
		}
	}
	s = l76SSHKey.ReplaceAllString(strings.Join(keep, "\n"), "<ssh public key masked>")
	return l76MaskLong(l76Hashed.ReplaceAllString(s, "<masked>"))
}

// l76Grep keeps the lines of text that contain any key, ignoring case.
func l76Grep(text string, keys []string) string {
	var keep []string
	for _, ln := range strings.Split(strings.TrimRight(text, "\n"), "\n") {
		low := strings.ToLower(ln)
		for _, k := range keys {
			if strings.Contains(low, strings.ToLower(k)) {
				keep = append(keep, ln)
				break
			}
		}
	}
	return strings.Join(keep, "\n")
}

// l76Leaks names what text must not hold: any of secrets (by index, never by
// value), any hash, any JWT.
func l76Leaks(text string, secrets []string) []string {
	var out []string
	for i, s := range secrets {
		if s != "" && strings.Contains(text, s) {
			out = append(out, fmt.Sprintf("secret #%d", i))
		}
	}
	if l76Hashed.MatchString(text) {
		out = append(out, "a hash")
	}
	if strings.Contains(text, "eyJ") {
		out = append(out, "a JWT")
	}
	if l76SSHKey.MatchString(text) {
		out = append(out, "an SSH public key")
	}
	return out
}

// l76Session is one row of `show system aaa authentication session`
// (SA#display-user-session-information). Current is the row's trailing
// `*` on the user name.
type l76Session struct {
	ID, User, Service, Method, PrivLvl, TTY string
	Current                                 bool
}

// l76Sessions reads the rows of the session table whose first cell is a
// number. Header rows, borders and a wrapped login-time line are skipped.
func l76Sessions(out string) []l76Session {
	var rows []l76Session
	for _, ln := range strings.Split(out, "\n") {
		cells := strings.Split(strings.TrimSpace(ln), "|")
		if len(cells) < 8 {
			continue
		}
		c := make([]string, len(cells))
		for i := range cells {
			c[i] = strings.TrimSpace(cells[i])
		}
		id := c[1]
		if id == "" || strings.Trim(id, "0123456789") != "" {
			continue
		}
		user, cur := strings.CutSuffix(c[2], "*")
		rows = append(rows, l76Session{ID: id, User: user, Service: c[3], Method: c[4], PrivLvl: c[5], TTY: c[6], Current: cur})
	}
	return rows
}

// l76SessionHead opens one entry of YANG `list session` (srl_nokia-aaa.yang
// 487) as `info from state system aaa authentication session` prints it.
var l76SessionHead = regexp.MustCompile(`^\s*session\s+\S+\s*\{\s*$`)

// l76UserSessions is the `session <id> { ... }` blocks of a session-state
// read whose `username` leaf is exactly user, joined, or "". A block that
// never closes is not read.
func l76UserSessions(text, user string) string {
	var blocks []string
	lines := strings.Split(text, "\n")
	for i := 0; i < len(lines); i++ {
		if !l76SessionHead.MatchString(lines[i]) {
			continue
		}
		depth, j := 0, i
		for ; j < len(lines); j++ {
			depth += strings.Count(lines[j], "{") - strings.Count(lines[j], "}")
			if depth == 0 {
				break
			}
		}
		if j == len(lines) {
			break
		}
		block := lines[i : j+1]
		for _, ln := range block {
			if f := strings.Fields(ln); len(f) == 2 && f[0] == "username" && f[1] == user {
				blocks = append(blocks, strings.Join(block, "\n"))
				break
			}
		}
		i = j
	}
	return strings.Join(blocks, "\n")
}

// l76RolesIn is the lab's roles (p49-read, p49-admin) that user's sessions
// hold (YANG `leaf-list role`, srl_nokia-aaa.yang 550), sorted. Other
// users' sessions are never read: a break-glass session the device still
// holds must not read as roles this user got (pre-flight I2).
func l76RolesIn(text, user string) []string {
	own := l76UserSessions(text, user)
	var out []string
	for _, r := range []string{"p49-admin", "p49-read"} {
		if regexp.MustCompile(`\b` + r + `\b`).MatchString(own) {
			out = append(out, r)
		}
	}
	return out
}

// l76CiteKnown says whether every part of cite is one of the cite kinds.
func l76CiteKnown(cite string) bool {
	if cite == "" {
		return false
	}
	for _, part := range strings.Split(cite, "; ") {
		if !(strings.HasPrefix(part, "SA#") || strings.HasPrefix(part, "CM#") || strings.HasPrefix(part, "CLAB#") ||
			strings.HasPrefix(part, "YANG ") || part == "HELP" || strings.HasPrefix(part, "HELP (")) {
			return false
		}
	}
	return true
}

// l76CiteURL is where one cite part is read: its page and anchor, the
// image's models, or the image's sr_cli --help.
func l76CiteURL(part string) string {
	anchor := func(p string) string {
		a, _, _ := strings.Cut(p, " ")
		return a
	}
	switch {
	case strings.HasPrefix(part, "SA#"):
		return l76SAURL + "#" + anchor(strings.TrimPrefix(part, "SA#"))
	case strings.HasPrefix(part, "CM#"):
		return l76CMURL + "#" + anchor(strings.TrimPrefix(part, "CM#"))
	case strings.HasPrefix(part, "CLAB#"):
		return l76CLABURL + "#" + anchor(strings.TrimPrefix(part, "CLAB#"))
	case strings.HasPrefix(part, "YANG "):
		return "/opt/srlinux/models in " + l76Image
	default:
		return "sr_cli --help in " + l76Image
	}
}

// l76SourcesSection is the note's Sources: one line per l76Sources row,

// l76IdentityBase is the base of YANG identity name, without its prefix.

// invalid ends the run with no note. Its message passes the log filter.
// A restore that fails inside a deferred call after an earlier INVALID
// (the test is already failing and unwinding) is logged, not raised again,
// so the first INVALID's reason stays the run's reason.
func (e *l76Env) invalid(format string, args ...any) {
	e.t.Helper()
	msg := l76FilterLog(fmt.Sprintf(format, args...))
	if e.t.Failed() {
		e.t.Logf("also INVALID, while restoring after the first: %s", msg)
		return
	}
	e.dumpDevice()
	e.t.Fatalf("INVALID: %s", msg)
}

// dumpDevice keeps the device's own view of an INVALID run, best-effort, in
// the git-ignored tests/lab/logs/L76-invalid-<stamp>/, so the next attempt
// does not re-boot blind (pre-flight I6): the masked running config, the AAA
// log's last 400 lines and the session table. Each passes through
// l76FilterLog and then l76Leaks; a file with a hit is withheld. It never
// writes to results/ or evidence/, and it never raises: it calls sr and
// aaaTail, not running or invalid, and logs its own failures, so the INVALID
// that called it stays the run's reason.
func (e *l76Env) dumpDevice() {
	if e.dumped {
		return
	}
	e.dumped = true
	dir := filepath.Join(root, "tests", "lab", "logs", "L76-invalid-"+time.Now().UTC().Format("20060102T150405Z"))
	if err := os.MkdirAll(dir, 0o700); err != nil {
		e.t.Logf("INVALID dump: %v", err)
		return
	}
	secrets, err := e.secrets()
	if err != nil {
		e.t.Logf("INVALID dump: the run's seed tokens: %v; checking the other secrets only", err)
	}
	run, _, runErr := e.sr(60*time.Second, l76ReadRunning)
	aaa, aaaErr := e.aaaTail()
	sess, _, sessErr := e.sr(60*time.Second, l76ReadSessions)
	type read struct {
		text string
		err  error
	}
	for name, r := range map[string]read{
		"running.txt":  {l76MaskConfig(run), runErr},
		"aaa-log.txt":  {aaa, aaaErr},
		"sessions.txt": {sess, sessErr},
	} {
		text := r.text
		if r.err != nil {
			text = fmt.Sprintf("(not read cleanly: %v)\n%s", r.err, text)
		}
		text = l76FilterLog(text)
		if leaks := l76Leaks(text, secrets); len(leaks) > 0 {
			e.t.Logf("INVALID dump: %s withheld: it holds %v", name, leaks)
			continue
		}
		if err := os.WriteFile(filepath.Join(dir, name), []byte(text+"\n"), 0o600); err != nil {
			e.t.Logf("INVALID dump: %s: %v", name, err)
		}
	}
	e.t.Logf("INVALID dump: the device's view is in %s", dir)
}

// secrets is every secret the run knows, for the leak gates: the lab key,
// the break-glass password, SR Linux's default admin password, the wrong key
// and password, and every seed token. If the seeds cannot be read it returns
// the others, and the error.
func (e *l76Env) secrets() ([]string, error) {
	fixed := []string{labKeyDefault, breakglassPassword, l76AdminDefault, e.wrongKey, e.wrongPassword}
	runSeedsMu.Lock()
	seeds, err := labcreds.SecretsOf(runSeeds)
	runSeedsMu.Unlock()
	if err != nil {
		return fixed, err
	}
	return append(fixed, seeds...), nil
}

// sr runs sr_cli -d in the node as the container's root, outside TACACS+,
// and returns its output unfiltered: callers filter before keeping it.
// docker exec runs as root because containerlab starts SR Linux nodes with
// user 0:0 (its nodes/srl/srl.go; the image's own default is user:user).
func (e *l76Env) sr(within time.Duration, args ...string) (string, time.Duration, error) {
	ctx, cancel := context.WithTimeout(context.Background(), within)
	defer cancel()
	argv := append([]string{"exec", l76Container, "sr_cli", "-d"}, args...)
	start := time.Now()
	out, err := exec.CommandContext(ctx, "docker", argv...).CombinedOutput()
	return string(out), time.Since(start), err
}

// set applies one flat `set /` line (CLAB#cli's flat form) and reads it back.
// It tries `sr_cli -d --candidate-mode --commit-at-end -- <line>`, the form
// sr_cli's own help example shows (HELP; pre-flight M8). If the read-back
// says that did not apply, it sends `enter candidate`, the line and `commit
// now` on stdin (CM#configuration-modes,
// CM#commit-configuration-in-candidate-mode). If neither applies, the run is
// INVALID.
func (e *l76Env) set(line string, applied func(running string) bool) {
	e.t.Helper()
	out, _, err := e.sr(90*time.Second, "--candidate-mode", "--commit-at-end", "--", line)
	if err == nil && applied(e.running()) {
		return
	}
	first := l76MaskConfig(out)
	ctx, cancel := context.WithTimeout(context.Background(), 90*time.Second)
	defer cancel()
	cmd := exec.CommandContext(ctx, "docker", "exec", "-i", l76Container, "sr_cli", "-d")
	cmd.Stdin = strings.NewReader("enter candidate\n" + line + "\ncommit now\n")
	out2, err2 := cmd.CombinedOutput()
	if !applied(e.running()) {
		e.invalid("%q did not apply: sr_cli --candidate-mode --commit-at-end said (%v) %s; stdin said (%v) %s",
			line, err, first, err2, l76MaskConfig(string(out2)))
	}
}

// try is one SSH login and how long the device took to answer it. A dial
// that fails before authentication (a TCP reset or an EOF, not
// isAuthRejection) is retried once after 5 s; both attempts are recorded in
// e.retries for the note, and the second is the one returned (pre-flight
// M3: L73's XRd reset, d03ca159).
func (e *l76Env) try(user, pw string) (time.Duration, error) {
	once := func() (time.Duration, error) {
		start := time.Now()
		c, err := e.l.dial(user, pw, 60*time.Second)
		took := time.Since(start)
		if err == nil {
			c.Close()
		}
		return took, err
	}
	took, err := once()
	if err == nil || isAuthRejection(err) {
		return took, err
	}
	time.Sleep(5 * time.Second)
	took2, err2 := once()
	again := "logged in"
	if err2 != nil {
		again = oneLine(err2.Error())
	}
	e.retries = append(e.retries, fmt.Sprintf("`%s`: the first dial failed before authentication after %v (%s); "+
		"retried after 5 s: %s after %v", user, took.Round(time.Millisecond), oneLine(err.Error()), again,
		took2.Round(time.Millisecond)))
	return took2, err2
}

// tokenLogin spends one seed token on a login that runs l76Commands (Task
// 4), and returns the user, the outputs and the user's records. Each command
// has 60 s (loginWithin; pre-flight I1): a command the device never answers
// is closed, and err is a *notObserved naming it, rather than a run that
// waits until -test.timeout. outs holds one entry per command that was sent,
// so callers check len(outs). The records wait for the redeem and for two
// accounting records, or 30 s.
func (e *l76Env) tokenLogin(label string) (string, []string, []map[string]any, error) {
	e.t.Helper()
	off := e.l.mark()
	user, secret := e.l.nextLogin(e.t)
	outs, err := e.l.loginWithin(user, secret, 60*time.Second, l76Commands...)
	recs := e.l.waitForRecords(off, 30*time.Second, func(rs []map[string]any) bool {
		return redeemFor(rs, user) != nil && l76Count(l76Of(rs, user), "account") >= 2
	})
	for i, o := range outs {
		e.evidence[fmt.Sprintf("%s-%d.txt", label, i+1)] = "$ " + l76Commands[i] + "\n" + l76FilterLog(o)
	}
	return user, outs, l76Of(recs, user), err
}

// l76SessionOf is user's row in the session table, or nil.
func l76SessionOf(out, user string) *l76Session {
	for _, s := range l76Sessions(out) {
		if s.User == user {
			return &s
		}
	}
	return nil
}

## What port49 would need (findings, not code)

These are findings for the plan that adds a `nokia_srlinux` adapter. Each one says what it rests on: the 26.7 docs and YANG now, and the L76 cell that measures it. Rule 1 holds until the run: a finding cited to a cell is unmeasured until L76 closes.

1. **A platform-set entry `nokia_srlinux`.** Today the device runs the generic adapter (spec §8 "Unknown platforms"): `priv-lvl` only, `supports: [session]`. That is close to what SR Linux is:
   - **Session only.** The 26.7 SR Linux native schema has no TACACS+ per-command authorization method: `aaa-authorization-methods-config` and `aaa-authorization-events-top` are defined in `srl_nokia-aaa.yang` and never used (YANG; cell (b) counts `authorize_command`). The image's OpenConfig model does use them; OpenConfig mode is a separate, unmeasured question. The adapter declares `supports: [session]` and never sends a command reply.
   - **The session service** is `shell` (SA#authorization-use-tacacsx-server; cell (b) reads `request.service`). That is the table's fallback already. A `sessionServices` entry `"nokia_srlinux": {"shell"}` makes it measured rather than assumed, once (b) agrees.
2. **Privilege to role mapping.**
   - SR Linux maps the reply's `priv-lvl` to every local role whose `tacacs priv-lvl` is at or below it (SA#authorization-use-tacacsx-server; cells (h) and (b)). The device's own config owns the mapping, the way Junos's local classes do.
   - So port49's projection is a priv-lvl per grant. The reference config defines the roles per level: here `p49-read` at 1 and `p49-admin` at 15, each with `system configuration role` rules (SA#configuring-role).
   - The adapter's capability rows are those levels.
3. **Nokia VSAs as an optional projection.**
   - With `service-request` enabled, SR Linux asks for Nokia services (SA#configuring-tacacs-authorization-with-vsas; cell (j)). A reply can carry roles, or per-session allow and deny command lists: `allow-commandN`/`deny-commandN` up to 100 characters each, `ruleN`/`actionN` up to 255, at most 126 (SA#tacacs-services-vsas).
   - That is a session-time command projection, like Junos's `allow-commands`/`deny-commands` (decision 22). It is bounded, and it fails closed on overflow.
   - It is a later capability, not the adapter's first cut. The first cut is priv-lvl only.
4. **Security: `priv-lvl-authorization` defaults to false.**
   - With the default, a TACACS+-authenticated user gets full admin, and no authorization request reaches port49 (YANG description; cell (i)).
   - port49 then sees only the authentication and cannot bound the session.
   - The reference config must set `priv-lvl-authorization true`.
   - For the future SR Linux platform-set plan (Ruling 2): `check-config` could warn when a `nokia_srlinux` device redeems with no `authorize_session` after it. If that plan adopts the warning, it goes into the spec §12 table before any code. This plan makes no spec edit.
5. **A port49 deny falls through to local by default.** `exit-on-reject` defaults to false (YANG; cell (d)), so a person with a local account gets past a port49 deny. Plan 12's reference config sets `exit-on-reject` (Ruling 1).
6. **Accounting is command-only.** SR Linux accounts each CLI command as a whole string, start and stop, with no exec session start or stop (SA#configuring-account; cell (c)).
   - port49's context lifecycle (§5.6) can't rely on an accounting STOP to end a session on this platform. It ends on the session ceiling and the idle path, as on any device that sends none.
   - The `account_gap` logic must not read the absence of exec records as a gap.
7. **Health checks and recovery.**
   - SR Linux opens and closes a TCP connection to each server every 30 s (`health-check`, SA#aaa-server-group-configuration; cell (g)).
   - port49 returns silently from a connection that sends nothing, so the health checks write no records. Cell (g) measures how many there are.
   - Cell (g)'s recovery time after a restart is the window in which a port49 user is refused after port49 comes back. Plan 12's runbook states it.
8. **The secret.** `secret-key` takes up to 128 characters of cleartext (YANG), so port49's generated keys fit. The device stores it as `$aes1$...`, reversible on the box. The secret-handling doc should say so.
9. **The name.** The inventory platform is `nokia_srlinux`, containerlab's kind name, which NetBox-style slugs also use. A `platform_aliases` entry for `srlinux` and `sr_linux` follows the existing alias pattern (`internal/sot/alias.go`).
