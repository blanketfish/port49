# Plan 2: Token Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The full token semantics on top of plan 1, against the `(nas, username)` key the lab
forced: the complete store record set with encryption at rest, a **sliding receipt** in place of
the withdrawn `reusable` flag, an enable path that updates privilege in place and keeps `ctx_id`,
login context in its §5.1.1 shape with every teardown row that still has content, accounting
annotation on a per-platform session discriminator, and an in-process mint function plan 3's
broker wraps.

**Architecture:** `internal/token` owns the token format and the `Minter`. `internal/store` grows
to the full record set of design §12; `internal/store/crypt` is a decorating `Store` that seals
every credential-bearing record with AES-256-GCM under a two-key window, so the in-memory store and
every future backend hold ciphertext — with one deliberate exception, the `contexts_by_principal`
index, argued in Task 5. The plan-1 handlers gain the checks the spec puts on their paths.
`internal/session` holds the broker-side operations that touch live context (refresh, revocation)
as plain functions over the store, with no HTTP yet. `internal/username` is a new leaf package
holding `Canonical`: the daemon imports `internal/token` from Task 7 on, and the minter has to
enforce the canonicalization invariant, so the canonicalizer cannot live in `internal/daemon/authen`
without a cycle (Task 1).

**Tech Stack:** Go 1.22, standard library (`crypto/aes`, `crypto/cipher`, `crypto/hmac`,
`crypto/sha256`), the plan-1 packages. No new dependencies. Nothing here needs containerlab; the
lab is not run by this plan, and the two lab files this plan edits are checked with
`go vet -tags lab ./tests/lab/...` only.

**Spec:** `docs/design/2026-08-21-port49-design.md` §8 (all of it), §12 "Store interface", §17
"Minting" and "Requirements" (idempotency only); `docs/design/2026-08-23-policy-engine-spec.md`
§5.1.1, §5.1.3, §5.1.4, §5.3, §5.6, §5.7, §5.8, §7, §13 decisions 15 and 22, §15 rows L1, L3, L13,
L15, L16, L17, L18. Roadmap entry: `docs/superpowers/plans/README.md`, "Plan 2".
**Prerequisite:** plan 1 merged (PR #2) and the lab work on `feature/lab-l4-fallthrough`; this plan
modifies files both created.

## What this plan is, and what it replaced

This file replaces `2026-09-06-02-token-model.md`, which was written from plan 1's *text* and
assumed the `(nas, port)` login-context key. That key was measured and did not survive: on no
platform in the lab is `port` the same value at authentication and at authorization
(`tests/lab/results/L1-arista_eos.md`, `L1-cisco_nxos.md`, `L1-juniper_vsrx.md`,
`L1-juniper_vjunos-router.md`; the one exception, Catalyst 8000V, is in `L1-cisco_iosxe.md`). The
key is now `(nas, username)` and the receipt `(nas, username, credential_sha256)` (spec §13,
decision 15). `docs/superpowers/plans/2026-09-20-plan-2-revision-notes.md` is the line-by-line
list of what that broke and the owner's rulings; every one of them is carried here. The five
substantive changes from the old draft:

1. **Teardown row 5 is deleted, not re-keyed.** Under `(nas, username)` a START under a different
   username addresses a different context (spec §5.6, row 5, withdrawn 2026-09-20). The old plan's
   Task 5 step 1 and its `TestRow5RejectedAuthInvalidatesForeignContext` are gone.
2. **`reusable` is withdrawn; the receipt slides.** `receipt_idle_ttl` (15m) and `receipt_max_age`
   (2h) replace the fixed 30 s `receipt_ttl` (spec §13, decision 15, ruled 2026-09-22).
3. **The enable path has no `$enab{level}$` lookup and no `(nas, rem_addr)` index.** Every measured
   platform with an enable exchange puts the operator's own username on the START
   (`tests/lab/results/L3-arista_eos.md`, `L3-cisco_iosxe.md`; NX-OS 10.x has no enable exchange at
   all, `L3-nxos-cisco_nxos.md`). So no new reason code is minted for an ambiguity refusal that has
   no path to reach.
4. **Accounting binds on a per-platform session discriminator, not on `task_id` everywhere.**
   `task_id` restarts at `1` per session on both Junos images (`tests/lab/results/L1-juniper_vsrx.md`,
   `L1-juniper_vjunos-router.md`), so two concurrent logins both sent `task_id=1`.
5. **`contexts_by_principal` stays unencrypted, on a new argument.** The old justification ("the ref
   carries no identity") was never true — `nas` was always in the ref — and is now plainly false,
   because the ref carries the username. Task 5 carries the owner's replacement argument verbatim.

## Global Constraints

Copied verbatim from `CLAUDE.md`, "Code conventions":

- Go 1.22+, module `github.com/rhwendt/port49`, `gofmt` and `go vet` clean, no cgo.
- **snake_case everywhere it is data**: YAML keys, JSON log keys, config, metric names.
- Reason codes are the closed vocabulary of spec §5.7 (`internal/decision/reasons.go`).
  Never invent one; add to the spec table first.
- The log never contains a token, password, challenge, or response. Credentials appear only
  as `credential_sha256`. An unvalidated body is never logged.
- No device identity in metric labels.
- Verify before claiming done: run `make test && make vet` and report the real output.

Plan-specific, on top of plan 1's own Global Constraints, which all still apply:

- **Token = `tag ‖ secret`**, 6 + 24 base62 characters, no prefix.
  `tag = base62(HMAC-SHA256(tag_key, device_name))[:6]`, and
  `tag_key = HMAC-SHA256(current_encryption_key, "port49/tag")` — derived, never a second secret to
  distribute (design §8 "Device binding").
- **A daemon compares its own tag before any store access.** Mismatch is `device_mismatch` under PAP
  and ASCII; under CHAP the tag is invisible and the outcome stays `token_not_found`.
- **Tokens, receipts, login context, and idempotency records are encrypted at rest.** Blobs and the
  four indexes are not: blobs contain no identity, and the indexes are argued in Task 5.
- **Two-key window:** every write uses the current key; every read tries current then previous.
  Retiring the previous key is a config change, never code.
- **The candidate-set cap refuses the mint, never the redemption**, with a typed error naming the
  count. Default 8.
- **Accounting annotates and never deletes.** The teardown rows of spec §5.6 are the only things
  that discard context, and row 7 is advisory.
- **Refresh and revocation are broker operations**; the daemon never calls them. Here they are
  in-process functions with no transport.
- **Every claim about device behaviour in this plan cites a `tests/lab/results/` note by name.** A
  claim with no note is marked *unmeasured* and the code must not depend on it.
- Branch `feature/token-model`; never commit code to `main`.

### Task 1: `Canonical` moves to a leaf package

**Files:**
- Create: `internal/username/username.go`, `internal/username/username_test.go` (both moved)
- Modify: `internal/daemon/authen/username.go`

**Why this is first, and why it is a task rather than a footnote.** Two later tasks pull in opposite
directions on one import edge. Task 7 makes `internal/daemon/authen` import `internal/token` for the
device tag. Task 12's `minter_test.go` is an in-package `package token` test whose whole argument is
what canonicalization does to `İrem` — and if it reaches that through `authen.Canonical`, Go answers
`import cycle not allowed in test`. Not a vet warning: `go test ./internal/token` would not build,
so Task 12 Step 2 would never reach the failure it predicts and Step 4 could never pass.

Declaring the test `package token_test` would break the cycle and cost more than it saves: the
minter's `asciiUsername` would have to be exported or re-tested through `Mint`. Moving the
canonicalizer is the better fix because the mint needs the function itself, not just a test of it —
Task 12 refuses any username `Canonical` would change (`@`, `\` and case, not merely non-ASCII), and
it cannot enforce an invariant it cannot call. The new package imports `strings` and nothing else,
so nothing can cycle through it.

- [ ] **Step 1: Rewrite `internal/store/store.go`**

```go
// Package store is the narrow interface every shared record passes through
// (design §12). The record set is the store plan; implementations are
// pluggable, and memory is the reference.
package store

import (
	"context"
	"errors"
	"time"
)

var ErrNotFound = errors.New("store: not found")

type TokenKey struct {
	NAS      string // device name from admission
	Username string // canonical form
}

// Token kinds.
const (
	KindLogin  = "login"
	KindEnable = "enable"
)

// Credential is what a token and its login context record about the credential
// that authorized them (spec §5.1.4). It is identity, not a secret — the daemon
// never sees the credential itself — and it is sealed, because a store dump
// should not enumerate who was logged into which device (design §8).
type Credential struct {
	Method      string // cert | oidc | k8s
	Fingerprint string
	Issuer      string
	Serial      string
	Subject     string
	Iss         string
	Sub         string
	Sid         string
	ACR         string
	AMR         []string
}

type Token struct {
	// ID is a handle, not a credential. It is never presented on the wire —
	// the daemon chooses it and only the daemon ever says it — and it is
	// deliberately plaintext so the sealing layer can address a record it
	// cannot read: RedeemAndReceipt removes by ID, because it cannot compare a
	// sealed Secret inside the inner store. That is also why memory matches it
	// with `==` rather than crypto/subtle: nothing an attacker can influence
	// reaches this comparison.
	ID        string
	Secret    []byte // sealed
	Kind      string // KindLogin | KindEnable
	ExpiresAt time.Time

	Principal     string // sealed
	Username      string // sealed
	BlobHash      string
	MaxSessionAge time.Duration // minimum across the principal's roles (spec §5.1.1)
	Enable        string        // none | auto | token (spec §7)
	MaxPrivilege  uint8
	Credential    Credential // sealed
	AuthTime      time.Time

	Sealed []byte // written by internal/store/crypt; zero in plaintext form
}

// ReceiptKey addresses the short-lived proof of a completed redemption. The
// credential hash is part of the key, not merely recorded in the record: that
// is what makes a byte-identical retransmission the only thing that replays,
// while a genuinely new login by the same user finds nothing and redeems
// normally (design §8; spec §13, decision 15).
type ReceiptKey struct {
	NAS              string
	Username         string // canonical form
	CredentialSHA256 [32]byte
}

// Receipt is the sliding retry tolerance of design §8. Three timestamps, and
// they answer three different questions:
//
//   - FirstRedeemedAt anchors the absolute cap. It never moves.
//   - IdleExpiresAt is the sliding bound, pushed out by ExtendReceipt on every
//     re-presentation this receipt answers.
//   - RetainUntil is the store's own TTL, and it is deliberately later than
//     both: a presentation past a bound has to find the receipt in order to be
//     answered `token_spent` rather than `token_not_found` (spec §5.7). Past
//     RetainUntil the record is reclaimed and the answer degrades to
//     `token_not_found`, which is honest — by then the token is gone too.
type Receipt struct {
	// CredentialSHA256 repeats the key's hash. The lookup already selects on
	// it; this copy is what the constant-time compare in package authen checks
	// after the lookup, so a store answering with a record it was not asked
	// for is caught rather than replayed. It is deliberately redundant and
	// must not be "simplified" away.
	CredentialSHA256 [32]byte // sealed
	Status           uint8    // sealed; the authentication REPLY status that was sent
	CtxID            string   // sealed

	FirstRedeemedAt time.Time
	IdleExpiresAt   time.Time
	RetainUntil     time.Time

	Sealed []byte
}

// ReceiptWrite is the receipt half of RedeemAndReceipt. Principal is an index
// key, not a field of the record: it is written into receipts_by_principal so
// revocation can delete a principal's receipts (spec §13, decision 15), and it
// is passed separately precisely because the record itself is sealed and the
// index is not (Task 5's argument).
type ReceiptWrite struct {
	Key       ReceiptKey
	Receipt   Receipt
	Principal string
	IndexTTL  time.Duration
}

// ContextKey addresses the login context. It is (nas, username), and it
// deliberately does not mention the port: measured, `port` is not the same
// value at the authentication that writes the context and the authorization
// that reads it on any platform in the lab (spec §13, decision 15; §15, L1).
// One consequence is accepted rather than fixed: two concurrent logins by one
// username on one device share this key.
type ContextKey struct {
	NAS      string
	Username string // canonical form
}

type Context struct {
	CtxID     string // sealed
	Principal string // sealed
	Username  string // sealed
	// Port and RemAddr are recorded as the device presented them at
	// authentication. They are attributes, never part of any key; RemAddr is
	// compared on the enable exchange (spec §5.6).
	Port     string // sealed
	RemAddr  string // sealed
	PrivLvl  uint8
	BlobHash string

	Credential     Credential // sealed
	AuthTime       time.Time
	SessionExpires time.Time // auth_time + max_session_age; zero means no ceiling
	RefreshedAt    time.Time // the staleness clock (spec §5.1.1)
	RevokedAt      time.Time // set by revocation; denies until the idle TTL reclaims
	// LastTouchedAt is when this record's expiry was last extended. It is
	// bookkeeping about the TTL, not about the session: the authorizer reads it
	// to decide whether an extension is due at all, so a steady operator costs
	// one store write per half of the idle TTL instead of one per command
	// (spec §5.6; Task 10). PutContext and TouchContext both stamp it; it is
	// plaintext, because it is a clock and not an identity.
	LastTouchedAt time.Time

	// SessionDiscriminator is the value of whatever AV pair separates two
	// sessions of one user on one device, per platform (spec §5.8). It is
	// §5.1.1's `task_id` slot under the name the lab forced: `task_id` restarts
	// at 1 per session on both Junos images
	// (tests/lab/results/L1-juniper_vsrx.md, L1-juniper_vjunos-router.md).
	SessionDiscriminator string // sealed
	AccountingState      string // "" | "open" | "closing"; advisory, never authorizes

	Enable       string // copied from the token: none | auto | token
	MaxPrivilege uint8
	CreatedAt    time.Time

	Sealed []byte
}

// ContextRef is what the indexes hold: the context key, nothing more.
type ContextRef struct {
	NAS      string
	Username string
}

type Idempotency struct {
	BodyHash  string
	Response  []byte // sealed — it contains the minted tokens (design §17)
	ExpiresAt time.Time
	Sealed    []byte
}

type Store interface {
	PutToken(ctx context.Context, k TokenKey, t Token) (count int, err error)
	Candidates(ctx context.Context, k TokenKey) ([]Token, error)
	// RedeemAndReceipt removes the token with this ID and writes the receipt in
	// one atomic operation, indexing the receipt by principal (design §12).
	RedeemAndReceipt(ctx context.Context, k TokenKey, tokenID string, w ReceiptWrite) error
	DeleteTokens(ctx context.Context, k TokenKey) error
	GetReceipt(ctx context.Context, rk ReceiptKey) (Receipt, error)
	// ExtendReceipt pushes the sliding bound out. It never moves RetainUntil or
	// FirstRedeemedAt, so the absolute cap cannot be slid.
	ExtendReceipt(ctx context.Context, rk ReceiptKey, idleExpiresAt time.Time) error
	DeleteReceiptsByPrincipal(ctx context.Context, principal string) (int, error)

	PutContext(ctx context.Context, k ContextKey, c Context, ttl time.Duration) error
	GetContext(ctx context.Context, k ContextKey) (Context, error)
	// TouchContext extends this context's expiry to now+ttl. It writes exactly
	// two things, both plaintext bookkeeping about the extension itself: the
	// expiry, and LastTouchedAt. It never takes a Context from the caller.
	//
	// That is the whole point of it. Extending a TTL by reading the record and
	// writing it back discards everything written between the two, and one of
	// those writers is revocation: an extension racing RevokeByPrincipal writes
	// a copy whose RevokedAt is zero, and it stays zero — the receipts are
	// already deleted, so nothing sets it again. The operator's revocation
	// reports contexts touched and the session keeps working, silently, on the
	// highest-frequency path in the daemon. Accounting's annotation and the
	// enable path's privilege raise lose the same way.
	//
	// ErrNotFound if the key is absent or already expired, which is how the
	// caller learns it lost the race; PutContext cannot tell it that.
	TouchContext(ctx context.Context, k ContextKey, ttl time.Duration) error
	DeleteContext(ctx context.Context, k ContextKey) error

	// Task 3 appends here: PutBlob, GetBlob, BumpBlob, IndexContext,
	// UnindexContext, ContextsByPrincipal, ContextsBySid, ContextsByCert,
	// ReindexSid, ActivePrincipals, PutIdempotency, GetIdempotency.
}

// CertKey is the index key a CRL or OCSP response names (spec §5.1.4).
func CertKey(issuer, serial string) string { return issuer + "|" + serial }

// HasCeiling reports whether this context carries a session ceiling.
func (c Context) HasCeiling() bool { return !c.SessionExpires.IsZero() && !c.AuthTime.IsZero() }
```

```go
// Package token defines the device token: a keyed device tag followed by a
// random secret (design §8 "Device binding"), and the Minter that issues them.
package token

import (
	"crypto/hmac"
	"crypto/sha256"
	"io"
	"math/big"
)

const (
	TagLen    = 6
	SecretLen = 24
	Len       = TagLen + SecretLen
)

const alphabet = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz"

// TagKey derives the tag key from the current encryption-at-rest key so no new
// secret has to be distributed (design §8: "the same place the RFC 8907 shared
// keys already live"). It is derived rather than reused so that a compromise of
// one does not hand over the other in usable form.
func TagKey(currentEncryptionKey []byte) []byte {
	m := hmac.New(sha256.New, currentEncryptionKey)
	m.Write([]byte("port49/tag"))
	return m.Sum(nil)
}

// Tag is the first six characters of every token minted for deviceName. A
// daemon computes its own once and compares it before any store access, so a
// token cut for another device is recognized rather than merely absent.
func Tag(tagKey []byte, deviceName string) string {
	m := hmac.New(sha256.New, tagKey)
	m.Write([]byte(deviceName))
	return Base62(m.Sum(nil))[:TagLen]
}

// New mints a token: the device's tag followed by SecretLen random characters.
func New(r io.Reader, tagKey []byte, deviceName string) (string, error) {
	secret := make([]byte, SecretLen)
	for i := range secret {
		n, err := randInt(r, len(alphabet))
		if err != nil {
			return "", err
		}
		secret[i] = alphabet[n]
	}
	return Tag(tagKey, deviceName) + string(secret), nil
}

// Parse returns the tag of a presented credential if it has the token shape.
// A credential that is not token-shaped — a mistyped password — returns false
// and is never reported as a wrong device.
func Parse(presented []byte) (string, bool) {
	if len(presented) != Len {
		return "", false
	}
	for _, c := range presented {
		if !isAlphabet(c) {
			return "", false
		}
	}
	return string(presented[:TagLen]), true
}

func isAlphabet(c byte) bool {
	return (c >= '0' && c <= '9') || (c >= 'A' && c <= 'Z') || (c >= 'a' && c <= 'z')
}

// Base62 encodes bytes as a big-endian integer in the alphabet. Not
// length-preserving; used for tags, where only the prefix matters.
func Base62(b []byte) string {
	n := new(big.Int).SetBytes(b)
	if n.Sign() == 0 {
		return "0"
	}
	base := big.NewInt(int64(len(alphabet)))
	var out []byte
	mod := new(big.Int)
	for n.Sign() > 0 {
		n.DivMod(n, base, mod)
		out = append([]byte{alphabet[mod.Int64()]}, out...)
	}
	return string(out)
}

// randInt returns a uniform integer in [0, n) by rejection sampling: a plain
// modulo would bias the alphabet, and 143 bits of secret is the only thing
// standing between a guess and a device.
func randInt(r io.Reader, n int) (int, error) {
	limit := 256 - 256%n
	var b [1]byte
	for {
		if _, err := io.ReadFull(r, b[:]); err != nil {
			return 0, err
		}
		if int(b[0]) < limit {
			return int(b[0]) % n, nil
		}
	}
}
```

  ```go
  var ErrUnknownKey = errors.New("crypt: sealed under an unknown key")
  ```

  `m.CryptOpenFailures`.
- `internal/daemon/metrics` gains:
  ```go

  // key problem, not a missing record, and it is the one failure mode of the
  // rotation window that has no other symptom. Labels are the record kind only —
  // "token", "receipt", "context", "idempotency" — never a device or a user.
  ```

- Sealed, per record: **Token** — `Secret`, `Principal`, `Username`, `Credential`; **Receipt** —
  `CredentialSHA256`, `Status`, `CtxID`; **Context** — `CtxID`, `Principal`, `Username`, `Port`,
  `RemAddr`, `Credential`, `SessionDiscriminator`; **Idempotency** — `Response`. Everything needed
  for keying and expiry stays plaintext: `Token.ID`, `Kind`, `ExpiresAt`, `BlobHash`,
  `MaxSessionAge`, `Enable`, `MaxPrivilege`, `AuthTime`, the receipt's three timestamps, the
  context's `PrivLvl`, `BlobHash`, `SessionExpires`, `RefreshedAt`, `RevokedAt`, `LastTouchedAt`,
  `AccountingState`, `CreatedAt`, and `Idempotency.BodyHash`. `LastTouchedAt` is plaintext for the
  same reason `RevokedAt` is: `TouchContext` runs inside the inner store, which cannot open a seal.
- **Blobs pass through unsealed.** They contain no identity (design §12).

**The index exception, and why.** `principal`, `sid`, `certKey` and the receipt index are index keys
and are stored in plaintext. The old draft justified this with "the ref carries no identity on its
own"; that was never true — `nas` was always in the ref — and the ref now carries the username too.
The owner ruled on 2026-09-21, and this is the argument that replaces it, verbatim:

> a dump of the index reveals principal, device and login name; every credential-bearing record
> (token, receipt, context body) stays sealed; the index is protected by store access control rather
> than by encryption, because revocation is the path needed most on a bad day and must not depend on
> the encryption key or its rotation window being available.

**The receipt's second copy of the credential hash.** The sealed blob repeats the hash that is also
in the plaintext key. That leaks that two redemptions presented the same credential — which the old
plaintext `(nas, port, username)` key already leaked in a coarser form — and it is accepted: the
copy is what the post-lookup constant-time compare checks, so a store answering with a record it was
not asked for is caught rather than replayed (spec §5.7, `credential_mismatch`). It is deliberately
redundant and must not be removed.

```go
// Package crypt is the encryption-at-rest layer (design §8). It decorates a
// store.Store so that identity and credential fields are sealed before they
// reach any backend, under a current key with one previous key accepted.
//
// What is NOT sealed is deliberate and is argued in plan 2 Task 5: blobs (no
// identity) and the four indexes (revocation is the path needed most on a bad
// day and must not depend on the encryption key being available).
package crypt

import (
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"time"

	"github.com/prometheus/client_golang/prometheus"

	"github.com/rhwendt/port49/internal/store"
)

var ErrUnknownKey = errors.New("crypt: sealed under an unknown key")

type Key struct {
	ID    string
	Bytes [32]byte
}

type Keys struct {
	Current  Key
	Previous *Key
}

// Seal: len(id) ‖ id ‖ nonce ‖ AES-256-GCM(plaintext, aad=id). The key id
// travels with the ciphertext so a read knows which key to try first, and it
// is the AAD so a record cannot be re-labelled with another key's id.
func (k Keys) Seal(plaintext []byte) ([]byte, error) { return seal(k.Current, plaintext) }

func seal(key Key, plaintext []byte) ([]byte, error) {
	if len(key.ID) == 0 || len(key.ID) > 255 {
		return nil, errors.New("crypt: key id must be 1..255 bytes")
	}
	block, err := aes.NewCipher(key.Bytes[:])
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}
	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return nil, err
	}
	out := append([]byte{byte(len(key.ID))}, key.ID...)
	out = append(out, nonce...)
	return gcm.Seal(out, nonce, plaintext, []byte(key.ID)), nil
}

func (k Keys) Open(sealed []byte) ([]byte, error) {
	if len(sealed) < 1 {
		return nil, ErrUnknownKey
	}
	n := int(sealed[0])
	if len(sealed) < 1+n {
		return nil, ErrUnknownKey
	}
	id := string(sealed[1 : 1+n])
	var key *Key
	switch {
	case id == k.Current.ID:
		key = &k.Current
	case k.Previous != nil && id == k.Previous.ID:
		key = k.Previous
	default:
		return nil, ErrUnknownKey
	}
	block, err := aes.NewCipher(key.Bytes[:])
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}
	rest := sealed[1+n:]
	if len(rest) < gcm.NonceSize() {
		return nil, errors.New("crypt: short ciphertext")
	}
	return gcm.Open(nil, rest[:gcm.NonceSize()], rest[gcm.NonceSize():], []byte(id))
}

// The sealed portions, as JSON before encryption.
type tokenSecret struct {
	Secret     []byte           `json:"secret"`
	Principal  string           `json:"principal"`
	Username   string           `json:"username"`
	Credential store.Credential `json:"credential"`
}

type receiptSecret struct {
	CredentialSHA256 [32]byte `json:"credential_sha256"`
	Status           uint8    `json:"status"`
	CtxID            string   `json:"ctx_id"`
}

type contextSecret struct {
	CtxID                string           `json:"ctx_id"`
	Principal            string           `json:"principal"`
	Username             string           `json:"username"`
	Port                 string           `json:"port"`
	RemAddr              string           `json:"rem_addr"`
	Credential           store.Credential `json:"credential"`
	SessionDiscriminator string           `json:"session_discriminator"`
}

type wrapped struct {
	inner        store.Store
	keys         Keys
	openFailures *prometheus.CounterVec
}

func Wrap(inner store.Store, k Keys, openFailures *prometheus.CounterVec) store.Store {
	return &wrapped{inner: inner, keys: k, openFailures: openFailures}
}

// openErr is what every read returns when a record will not open. It is
// deliberately NOT store.ErrNotFound: that is the one store error every handler
// treats as ordinary — authen falls through to the candidate lookup, author
// denies context_missing, and all three packages label the metric "not_found",
// the same label an absent record produces. Collapsing a key failure into it
// makes a mis-set PORT49_ENC_V1 look exactly like every session on the fleet
// expiring at once, with nothing anywhere naming decryption. Handlers take
// their existing non-ErrNotFound branch instead — store_unavailable — which is
// honest: the store is unavailable to this daemon.
func (w *wrapped) openErr(record string, err error) error {
	if w.openFailures != nil {
		w.openFailures.WithLabelValues(record).Inc()
	}
	// err is already ErrUnknownKey when neither key id matched, and a GCM or
	// JSON failure when the key matched and the bytes did not; both are
	// wrapped as they are, so `errors.Is(err, ErrUnknownKey)` distinguishes
	// "wrong key" from "tampered record" at the call site.
	return fmt.Errorf("crypt: opening %s: %w", record, err)
}

func (w *wrapped) sealJSON(v any) ([]byte, error) {
	b, err := json.Marshal(v)
	if err != nil {
		return nil, err
	}
	return w.keys.Seal(b)
}

func (w *wrapped) openJSON(sealed []byte, v any) error {
	b, err := w.keys.Open(sealed)
	if err != nil {
		return err
	}
	return json.Unmarshal(b, v)
}

func (w *wrapped) sealToken(t store.Token) (store.Token, error) {
	s, err := w.sealJSON(tokenSecret{Secret: t.Secret, Principal: t.Principal, Username: t.Username, Credential: t.Credential})
	if err != nil {
		return store.Token{}, err
	}
	t.Secret, t.Principal, t.Username, t.Credential, t.Sealed = nil, "", "", store.Credential{}, s
	return t, nil
}

func (w *wrapped) openToken(t store.Token) (store.Token, error) {
	var ts tokenSecret
	if err := w.openJSON(t.Sealed, &ts); err != nil {
		return store.Token{}, err
	}
	t.Secret, t.Principal, t.Username, t.Credential, t.Sealed = ts.Secret, ts.Principal, ts.Username, ts.Credential, nil
	return t, nil
}

func (w *wrapped) PutToken(ctx context.Context, k store.TokenKey, t store.Token) (int, error) {
	st, err := w.sealToken(t)
	if err != nil {
		return 0, err
	}
	return w.inner.PutToken(ctx, k, st)
}

func (w *wrapped) Candidates(ctx context.Context, k store.TokenKey) ([]store.Token, error) {
	raw, err := w.inner.Candidates(ctx, k)
	if err != nil {
		return nil, err
	}
	out := make([]store.Token, 0, len(raw))
	for _, t := range raw {
		ot, err := w.openToken(t)
		if err != nil {
			// Sealed under a retired key: unreadable, therefore unredeemable.
			// Returning it with a zero Secret would match a zero-length
			// credential, so it is dropped; expiry reclaims the record. This is
			// the one read that must NOT fail the call — one unreadable token
			// in a candidate set of eight must not deny the seven — so the
			// counter is the only place it is visible. That is what
			// crypt_open_failures_total{record="token"} is for.
			_ = w.openErr("token", err)
			continue
		}
		out = append(out, ot)
	}
	return out, nil
}

func (w *wrapped) RedeemAndReceipt(ctx context.Context, k store.TokenKey, tokenID string, wr store.ReceiptWrite) error {
	s, err := w.sealJSON(receiptSecret{CredentialSHA256: wr.Receipt.CredentialSHA256, Status: wr.Receipt.Status, CtxID: wr.Receipt.CtxID})
	if err != nil {
		return err
	}
	wr.Receipt.CredentialSHA256, wr.Receipt.Status, wr.Receipt.CtxID, wr.Receipt.Sealed = [32]byte{}, 0, "", s
	return w.inner.RedeemAndReceipt(ctx, k, tokenID, wr)
}

func (w *wrapped) GetReceipt(ctx context.Context, rk store.ReceiptKey) (store.Receipt, error) {
	r, err := w.inner.GetReceipt(ctx, rk)
	if err != nil {
		return store.Receipt{}, err
	}
	var rs receiptSecret
	if err := w.openJSON(r.Sealed, &rs); err != nil {
		return store.Receipt{}, w.openErr("receipt", err)
	}
	r.CredentialSHA256, r.Status, r.CtxID, r.Sealed = rs.CredentialSHA256, rs.Status, rs.CtxID, nil
	return r, nil
}

func (w *wrapped) PutContext(ctx context.Context, k store.ContextKey, c store.Context, ttl time.Duration) error {
	s, err := w.sealJSON(contextSecret{CtxID: c.CtxID, Principal: c.Principal, Username: c.Username,
		Port: c.Port, RemAddr: c.RemAddr, Credential: c.Credential, SessionDiscriminator: c.SessionDiscriminator})
	if err != nil {
		return err
	}
	c.CtxID, c.Principal, c.Username, c.Port, c.RemAddr, c.Credential, c.SessionDiscriminator, c.Sealed =
		"", "", "", "", "", store.Credential{}, "", s
	return w.inner.PutContext(ctx, k, c, ttl)
}

func (w *wrapped) GetContext(ctx context.Context, k store.ContextKey) (store.Context, error) {
	c, err := w.inner.GetContext(ctx, k)
	if err != nil {
		return store.Context{}, err
	}
	var cs contextSecret
	if err := w.openJSON(c.Sealed, &cs); err != nil {
		return store.Context{}, w.openErr("context", err)
	}
	c.CtxID, c.Principal, c.Username, c.Port, c.RemAddr, c.Credential, c.SessionDiscriminator, c.Sealed =
		cs.CtxID, cs.Principal, cs.Username, cs.Port, cs.RemAddr, cs.Credential, cs.SessionDiscriminator, nil
	return c, nil
}

func (w *wrapped) PutIdempotency(ctx context.Context, principal, key string, rec store.Idempotency) error {
	s, err := w.keys.Seal(rec.Response)
	if err != nil {
		return err
	}
	rec.Response, rec.Sealed = nil, s
	return w.inner.PutIdempotency(ctx, principal, key, rec)
}

func (w *wrapped) GetIdempotency(ctx context.Context, principal, key string) (store.Idempotency, error) {
	rec, err := w.inner.GetIdempotency(ctx, principal, key)
	if err != nil {
		return store.Idempotency{}, err
	}
	resp, err := w.keys.Open(rec.Sealed)
	if err != nil {
		return store.Idempotency{}, w.openErr("idempotency", err)
	}
	rec.Response, rec.Sealed = resp, nil
	return rec, nil
}
```

```
cap  := r.FirstRedeemedAt.Add(receiptMaxAge)
if !now.Before(cap)              → FAIL token_spent      (absolute cap)
if !now.Before(r.IdleExpiresAt)  → FAIL token_spent      (sliding bound)
next := now.Add(receiptIdleTTL); if next.After(cap) { next = cap }
ExtendReceipt(rk, next)          → ok:        PASS receipt_replayed, adopting r.CtxID
                                 → NotFound:  FAIL token_spent      (revoked mid-request)
                                 → other:     ERROR store_unavailable
```

On the write side, `RedeemAndReceipt` writes
`FirstRedeemedAt: now`, `IdleExpiresAt: now+receiptIdleTTL`,
`RetainUntil: now+receiptMaxAge+receiptIdleTTL`, and `Principal: winner.Principal` with
`IndexTTL` equal to the retention. The retention is longer than both bounds on purpose: a
presentation past a bound has to *find* the receipt to be answered `token_spent`. Past retention the
record is gone and the answer degrades to `token_not_found` — stated rather than hidden, and by then
the token is gone too, so nothing passes that should not.

**Why these numbers.** They are the owner's, ruled 2026-09-22 (spec §13, decision 15). The sizing
case is the gap between two presentations on **one device**, not the length of one operation:
Ansible's linear strategy leaves a device idle for the whole fleet's pass between its own tasks, and
an image copy then a verify leaves it quiet for five to ten minutes. The lab measured that the
authentication count for a job belongs to the client, not the transport — 1 for anything holding one
SSH session or Ansible `cisco.nxos` over `httpapi`, against 28 for NAPALM `nxos` over the same
NX-API — and NAPALM `nxos` crossed the fixed 30 s window at 38.8 s with tasks 5–9 refused
`token_not_found` and nothing changed in the operator's hand
(`tests/lab/results/L15-clients-cisco_nxos.md`, `L15-clients-arista_eos.md`). A `reusable` flag
would have pushed that fact about a library into policy. **Unmeasured:** the 15-minute default has
not been checked against a linear-strategy run with a deliberate gap, and the eAPI `/login` cookie
flow is still open (L7, L15).

```go
// EnableUsername is what a platform's enable START carries in the `user`
// field. Every platform measured carries the operator's own username:
// vEOS 4.32.2F and Catalyst 8000V 17.13.01a, both with service=enable
// (tests/lab/results/L3-arista_eos.md, L3-cisco_iosxe.md), and NX-OS 10.x has

// been observed sending $enab{level}$.
//
// EnableEnab exists so the shape has a name and a refusal rather than an
// implementation nothing has ever exercised. config.Load refuses it.
const (
	EnablePrincipal = "principal"
	EnableEnab      = "enab"
)

// EnableUsernames is the built-in table: every known platform, principal.
func EnableUsernames() map[string]string {
	out := make(map[string]string, len(sessionServices))
	for name := range sessionServices {
		out[name] = EnablePrincipal
	}
	return out
}

func KnownEnableUsername(v string) bool { return v == EnablePrincipal || v == EnableEnab }
```

```go
// resolveEnableUsernames applies any platforms.<name>.enable_username override
// to the built-in table, and refuses `enab`.
//
// The $enab{level}$ enable path is unbuilt on purpose: it would need a
// (nas, rem_addr) secondary index, and rem_addr is measured identical for two
// concurrent sessions behind one bastion, so that index would have to refuse
// rather than guess — and its refusal needs a reason code spec §5.7 does not
// carry. None of that is worth building for a username form no device in this
// lab has ever sent.
func resolveEnableUsernames(c *Config, overrides map[string]PlatformConfig) error {
	c.EnableUsernames = platform.EnableUsernames()
	names := make([]string, 0, len(overrides))
	for name := range overrides {
		names = append(names, name)
	}
	sort.Strings(names)
	for _, name := range names {
		v := overrides[name].EnableUsername
		if v == "" {
			continue
		}
		if !platform.KnownEnableUsername(v) {
			return fmt.Errorf("config: platforms.%s.enable_username is %q; it must be %q or %q",
				name, v, platform.EnablePrincipal, platform.EnableEnab)
		}
		if v == platform.EnableEnab {
			return fmt.Errorf("config: platforms.%s.enable_username: %q is refused: no platform in the lab has been "+
				"measured sending that username form, and port49 does not ship an unexercised enable path for it. "+
				"Every platform with an enable exchange sends the operator's own username "+
				"(tests/lab/results/L3-arista_eos.md, L3-cisco_iosxe.md). To enable it, add a "+
				"tests/lab/results/ note showing a device sending it and lift this refusal with the code that reads it",
				name, platform.EnableEnab)
		}
		c.EnableUsernames[name] = v
	}
	return nil
}
```
`platform.Known(name)` is already checked for the same `platforms:` block by
`resolveSessionServices`; call `resolveEnableUsernames` immediately after it so a mistyped platform
name is still caught once.

### Task 9: The enable path — privilege in place, `ctx_id` kept

**Files:**
- Modify: `internal/daemon/authen/authen.go`
- Test: `internal/daemon/authen/authen_test.go`

Task 8 is the prerequisite: `enable: auto` is safe to build here only because
`enable_username: enab` cannot load.

**The bug this fixes, measured.** Plan 1 has no escalate path: its `redeem` treats an enable START
as an ordinary redemption of a `kind: enable` token, so it mints a fresh `ctx_id` and writes it over
the login context. On vEOS, one operator's whole sequence
(`tests/lab/results/L3-arista_eos.md`; spec §5.6 teardown row 1):

```
18:00:37.499  redeem            permit token_redeemed   port=ssh   priv=1   ctx=QOZ6DYFB
18:00:37.705  authorize_session permit context_matched  port=vty4  priv=1   ctx=QOZ6DYFB
18:00:38.673  redeem            permit token_redeemed   port=vty4  priv=15  ctx=TVGMSVTY  replaced_ctx_id=QOZ6DYFB
```

Spec §5.6 row 1 and §7 both say the opposite: an `enable` redemption updates `privilege` in place
and keeps `ctx_id`. This task is where that becomes true.

**Interfaces:** behaviour in `redeem`, on `s.start.Service == wire.AuthenServiceEnable`:
  1. The record's event is `escalate`, not `redeem`.
  2. Read the context at `(nas, Canonical(wire username))`. Absent → FAIL `context_missing`.
  3. `ctx.Enable == "none"` → FAIL `enable_refused`.
  4. `s.start.PrivLvl > ctx.MaxPrivilege` → FAIL `ceiling_exceeded`.
  5. `ctx.RemAddr != "" && remAddr != "" && ctx.RemAddr != remAddr` → FAIL `rem_addr_mismatch`.
  6. `ctx.Enable == "auto"` → PASS `escalation_granted` with no token consulted (spec §7: "Daemon
     resolves `(nas, username)` → login context, checks the ceiling, PASSes. Any password
     accepted"). This is safe to implement now precisely because `enable_username: enab` cannot
     load (Task 8): §5.6's restriction is that `auto` MUST NOT be available where `enable_username`
     is not `principal`, and here nothing else can be.
  7. Otherwise redeem a `kind: enable` token under `(nas, ctx.Username)` — plan 1's candidate filter
     already does the kind check and answers `token_kind_mismatch` for a login token at the enable
     prompt.
  8. **The `ctx_id` is decided before the redemption, not after it.** On the enable path it is
     `incumbent.CtxID`; `newCtxID()` is not called at all. The receipt carries the `ctx_id`, and a
     retransmitted enable — the exact case the receipt exists for, and what the sliding window is
     built to serve — replays it: a freshly minted id there would put a `ctx_id` in the decision log
     that appears in no context, no `authorize_*` record and no accounting record, and the join
     across the escalation would break on the replay (spec §5.6 row 1, §7).
  9. On success: **update the incumbent context in place** — set `PrivLvl`, keep `CtxID`,
     `Principal`, `Credential`, `BlobHash`, `AuthTime`, `SessionExpires`, `RefreshedAt` — and
     `PutContext` it. Never `newCtxID()`, never `IndexContext` again (the context is already
     indexed), never `replaced_ctx_id`.
 10. The record carries `principal` from the context and reason `escalation_granted`.

### Task 10: Authorization — the §5.3 checks, and `context_idle_ttl` made a true idle TTL

**Files:**
- Modify: `internal/daemon/author/author.go`
- Test: `internal/daemon/author/author_test.go` (extend)

**The `context_idle_ttl` ruling, and why.** Plan 1 sets the context TTL at `PutContext` and never
extends it; `GetContext` does not touch it. So the key named `context_idle_ttl` is an **absolute**
lifetime: at 12h it drops a context whose operator typed a command a second ago, and the operator
gets `context_missing` — "this session was not authenticated by port49" — about a session port49
authenticated. That is the 3am failure, and it is exactly what spec §5.6 warns about: "a short TTL
was previously doing security work it cannot do — it narrows a window without closing it, while
denying idle operators mid-session with `context_missing`."

**Decision: make it a true idle TTL, and keep the name.** Permitted activity extends it, which is
what §5.6's "It SHOULD be extended by activity" asks for. The absolute clock already exists and is
the compliance-relevant one: `session_expires = auth_time + max_session_age`, checked below.
Renaming the key instead would leave port49 with two absolute clocks and no idle one, and would make
the backstop the control — the thing §5.6 says it must not be. **A key named `context_idle_ttl` that
measures absolute age lies in its own name**, and the operator who reads the name is the one who
sets the number.

**How the extension is done, and the two things it must not be.**

*Not `PutContext`.* Re-putting the record read at the top of the request discards every write that
landed in between, and the writes that land there are the ones that matter. `RevokeByPrincipal`
(Task 13) sets `RevokedAt`; an extension racing it writes a copy whose `RevokedAt` is zero, and it
stays zero — the receipts are already deleted, so nothing sets it again. The operator's revocation
returns "1 context touched" and the session keeps working, silently, on both sides. `acct.Handle`'s
annotation and the enable path's privilege raise lose the same way, which turns into a false
`foreign` alarm and a `privilege_exceeded` immediately after a successful escalation. Plan 1's own
comment at `authen.go:249-255` already names the missing compare-and-set on `PutContext`; this task
must not widen that window from narrow to routine by opening it once per authorized command. So the
extension goes through `TouchContext` (Task 2), which writes the expiry and `LastTouchedAt` inside
the store's own lock and takes no record from the caller.

*Not once per command.* `LastTouchedAt` is on the record the handler already has in hand, so the
extension runs only when `now.Sub(c.LastTouchedAt) >= contextIdleTTL/2` — one store write per half
of the idle TTL per session, rather than one per command, on the path with the p99 < 5ms target. The
common command costs no store write at all, and the record can never be more than half a TTL from
being extended, so a working operator is never reclaimed. The old draft argued this needed "the
store to expose a record's remaining TTL"; it does not, because the handler can carry the clock in
the record it already writes.

**What this leaves plan 7.** The store's own expiry reclaims the idle case, so plan 7's sweep is no
longer needed for that. What plan 7 still owns is the **post-ceiling grace case** — §5.6 row 3's
reclaim of a context past `session_expires` plus `grace_window` — which is a different clock and is
not overlapped by anything here. `TouchContext` returning `ErrNotFound` also tells the handler when
it lost the race, which `PutContext` never could.

**This is the in-process mint function plan 3 wraps.** Plan 3's minimal broker calls
`(*Minter).Mint` behind `/v1/tokens`; nothing here knows about HTTP, and the roadmap's older
signature `token.Mint(device, username, kind, ttl, reusable)` is superseded — `reusable` was
withdrawn on 2026-09-22 and the kind is chosen by `WithEnable` plus the subject's mechanism.

**Behaviour:**
- `Subject.Username` is refused unless every byte is printable ASCII (0x21–0x7E) **and the name
  survives `username.Canonical` unchanged** — see below.
- TTL is clamped to `Subject.TokenTTL`.
- `WithEnable` with `Enable == "token"` mints a second token of `store.KindEnable` sharing the TTL;
  `WithEnable` with any other mechanism returns a login token alone and an empty `Enable` field, so
  a subject configured `enable: none` cannot be handed an escalation credential by a caller's flag.
- The cap is checked against `Candidates` before writing, and refuses the **mint** with a typed
  error naming the count; a race past it is tolerated, it is a backstop against a mint-loop defect
  rather than the operative bound (design §8). Tokens already issued stay usable.
- An idempotent replay returns the stored result and mints nothing; the same key with a different
  `BodyHash` is `ErrIdempotencyConflict` (design §17).
- Every mint emits one `mint` record with `token_sha256` per token and **never** the token, reason
  `grants_matched` — the policy question is plan 4's; here the caller has already decided.

**Why the guard is "canonical", not "ASCII", with the collision spelled out.** `Canonical` does
three things: `strings.ToLower(strings.TrimSpace(u))`, strip everything up to the last `\`, and
truncate at the first `@`. Go's simple case mapping folds **U+0130 (İ)** onto `i`, so `İrem` and
`irem` both canonicalize to `irem` — and under `(nas, username)` they are **one login context and
one token key**: either user's token redeems for either, and the other's commands authorize against
a context they never created.

An ASCII-only guard stops that one and misses the two that will actually happen. `0x21–0x7E`
**includes `@` and `\`**, so in a directory-backed deployment — where `alice@corp.example` and
`CORP\alice` are the normal forms, not exotic ones — the guard passes a name the daemon will
canonicalize to something else. The minter stores the username verbatim in the token key
(`store.TokenKey{NAS: r.Device, Username: r.Subject.Username}`) while the daemon looks up
`Canonical(wire)` (`authen.go:164`): the operator holds a valid 30-character token, the tag matches,
and every attempt is `token_not_found` with nothing anywhere saying why.

So the rule is the invariant the comment already states: **a device-facing username must survive
canonicalization unchanged**. That is also why Task 1 moved `Canonical` — the mint has to call it,
and it cannot import the daemon. Task 15's seed loop applies `username.Canonical` to the name it
passes, which the mint then finds already canonical; before this change the two callers disagreed
about whose job it was.

The daemon cannot refuse a name a device sends; the mint can. Unicode usernames in the *directory*
are unaffected: §2 derives the device-facing username at mint, and this constrains only what may be
derived.

```go
var ErrIdempotencyConflict = errors.New("token: idempotency key reused with a different body")

// ErrUsernameNotCanonical refuses a device-facing username that
// canonicalization would change. username.Canonical lowercases, strips a
// DOMAIN\ prefix and truncates at '@', and Go's simple case mapping folds
// U+0130 onto `i` — so `İrem`, `CORP\irem` and `irem@corp.example` all
// canonicalize onto `irem` and would share one (nas, username) context and one
// token key. A name that merely changes is just as bad in a quieter way: the
// mint writes the token under the name it was given while the daemon looks it
// up under Canonical(wire), so the operator holds a valid token that is
// `token_not_found` every time, with nothing saying why.
//
// The daemon cannot refuse a name a device sends; the mint can.
var ErrUsernameNotCanonical = errors.New("token: device-facing username must be printable ASCII and already canonical")

func asciiUsername(u string) bool {
	if u == "" {
		return false
	}
	for i := 0; i < len(u); i++ {
		if u[i] < 0x21 || u[i] > 0x7e {
			return false
		}
	}
	return true
}

// canonicalUsername is the invariant, not just the character set: printable
// ASCII AND unchanged by canonicalization. The ASCII half alone would admit
// `@` and `\`, which are 0x21–0x7E and are exactly the two rewrites a
// directory-backed deployment hits every day.
func canonicalUsername(u string) bool { return asciiUsername(u) && username.Canonical(u) == u }

type ErrTooManyOutstanding struct {
	Device, Username string
	Count, Cap       int
}

func (e *ErrTooManyOutstanding) Error() string {
	return fmt.Sprintf("token: %d unspent tokens for %s on %s (cap %d); stop minting and use the ones you have",
		e.Count, e.Username, e.Device, e.Cap)
}

type Minter struct {
	store  store.Store
	log    decision.Emitter
	rand   io.Reader
	tagKey []byte
	now    func() time.Time
	cap    int
}

func NewMinter(s store.Store, e decision.Emitter, r io.Reader, tagKey []byte, now func() time.Time, cap int) *Minter {
	return &Minter{store: s, log: e, rand: r, tagKey: tagKey, now: now, cap: cap}
}

func (m *Minter) Mint(ctx context.Context, r Request) (Result, error) {
	if !canonicalUsername(r.Subject.Username) {
		return Result{}, ErrUsernameNotCanonical
	}
	if r.IdempotencyKey != "" {
		if rec, err := m.store.GetIdempotency(ctx, r.Subject.Principal, r.IdempotencyKey); err == nil {
			if rec.BodyHash != r.BodyHash {
				return Result{}, ErrIdempotencyConflict
			}
			var res Result
			if err := json.Unmarshal(rec.Response, &res); err == nil {
				return res, nil
			}
		}
	}

	ttl := r.TTL
	if ttl <= 0 || ttl > r.Subject.TokenTTL {
		ttl = r.Subject.TokenTTL
	}
	key := store.TokenKey{NAS: r.Device, Username: r.Subject.Username}
	cands, err := m.store.Candidates(ctx, key)
	if err != nil {
		return Result{}, err
	}
	if len(cands) >= m.cap {
		// The cap refuses the mint, never the redemption: a runaway client is
		// told to stop while every token already issued stays usable (design §8).
		return Result{}, &ErrTooManyOutstanding{Device: r.Device, Username: r.Subject.Username, Count: len(cands), Cap: m.cap}
	}

	expires := m.now().Add(ttl)
	res := Result{ExpiresAt: expires, Username: r.Subject.Username}
	var hashes []string

	mint := func(kind string) (string, error) {
		secret, err := New(m.rand, m.tagKey, r.Device)
		if err != nil {
			return "", err
		}
		id, err := New(m.rand, m.tagKey, r.Device) // any random string is a removal handle
		if err != nil {
			return "", err
		}
		if _, err := m.store.PutToken(ctx, key, store.Token{
			ID: id[TagLen:], Secret: []byte(secret), Kind: kind, ExpiresAt: expires,
			Principal: r.Subject.Principal, Username: r.Subject.Username, BlobHash: r.BlobHash,
			MaxSessionAge: r.Subject.MaxSessionAge, Enable: r.Subject.Enable, MaxPrivilege: r.Subject.MaxPrivilege,
			Credential: r.Subject.Credential, AuthTime: r.Subject.AuthTime,
		}); err != nil {
			return "", err
		}
		sum := sha256.Sum256([]byte(secret))
		hashes = append(hashes, hex.EncodeToString(sum[:]))
		return secret, nil
	}

	if res.Login, err = mint(store.KindLogin); err != nil {
		return Result{}, err
	}
	if r.WithEnable && r.Subject.Enable == "token" {
		if res.Enable, err = mint(store.KindEnable); err != nil {
			return Result{}, err
		}
	}

	if r.IdempotencyKey != "" {
		body, _ := json.Marshal(res)
		_ = m.store.PutIdempotency(ctx, r.Subject.Principal, r.IdempotencyKey,
			store.Idempotency{BodyHash: r.BodyHash, Response: body, ExpiresAt: expires})
	}

	m.log.Emit(decision.Record{TS: m.now(), Event: decision.EventMint, Verdict: decision.VerdictPermit,
		Reason: decision.GrantsMatched, Principal: r.Subject.Principal,
		Auth:   &decision.Auth{Method: r.Subject.Credential.Method},
		Device: &decision.Device{Name: r.Device, Platform: r.Platform},
		Mint:   &decision.Mint{TokenSHA256: hashes, TTLSeconds: int(ttl.Seconds()), BlobHash: r.BlobHash}})
	return res, nil
}
```

- **Revocation marks, and deletes receipts.** Marking is spec §5.6 row 2: `revoked_at` is set so the
  next command is denied `credential_revoked` with a `server_msg` saying so, distinguishable from a
  session port49 never saw; row 6 reclaims the state. Deleting the receipts is decision 15's sliding
  window — a receipt outliving a revocation would let the revoked credential keep answering PASS
  `receipt_replayed` for up to `receipt_max_age`. Each context's principal is read from the record
  before it is marked, so a revocation by `sid` or by certificate deletes receipts too.
- **The daemon never calls these.** Plan 7's broker wraps them in `/v1/refresh`, `/v1/logout` and
  `/v1/tokens/revoke`.
- **Which refs are unreachable at the device** — a session-only platform, spec §13 decision 21 — is
  decided by the caller with the adapter set from plan 5. Here every ref is returned as touched, and
  the plan states rather than implies that on Junos a revocation reaches a context nobody will read
  (`tests/lab/results/L17-juniper_vsrx.md`: `authorization-time-interval` re-authorizes, and a

```go
func (m *Manager) mark(ctx context.Context, refs []store.ContextRef) ([]store.ContextRef, error) {
	// Collect principals while the contexts are still readable: a revocation
	// that leaves the receipts behind lets the revoked credential keep
	// replaying for up to receipt_max_age (spec §13, decision 15).
	principals := map[string]bool{}

		}

		}
	}
	return touched, err
}
```

```go
// EncryptionKeys is the two-key window: writes use Current, reads try Current
// then Previous. Retiring Previous is a config change, never code (design §8).
func (c Config) EncryptionKeys() (crypt.Keys, error) {
	cur, err := key32(c.encCurrent.ID, c.secrets[c.encCurrent.SecretEnv])
	if err != nil {
		return crypt.Keys{}, err
	}
	keys := crypt.Keys{Current: cur}
	if c.hasPrevious {
		p, err := key32(c.encPrevious.ID, c.secrets[c.encPrevious.SecretEnv])
		if err != nil {
			return crypt.Keys{}, err
		}
		keys.Previous = &p
	}
	return keys, nil
}

// key32 returns an error rather than a short key silently zero-padded. Load
// already refuses anything but 32 bytes, so this is the backstop that makes the
// silent case impossible to reach by another route — and it is what the error
// return in EncryptionKeys's signature is for.
func key32(id, secret string) (crypt.Key, error) {
	if len(secret) != 32 {
		return crypt.Key{}, fmt.Errorf("config: encryption key %q: secret must be exactly 32 bytes, got %d", id, len(secret))
	}
	var k crypt.Key
	k.ID = id
	copy(k.Bytes[:], secret)
	return k, nil
}
```
